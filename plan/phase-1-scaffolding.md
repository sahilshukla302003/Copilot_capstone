# Phase 1 — Project Scaffolding

## Goal
Set up the complete repository skeleton: all directories, base configuration files, CLAUDE.md, and README.md. Nothing is generated by agents yet — this phase creates the empty but correctly structured foundation that every subsequent phase builds on.

---

## Prerequisites
- GitHub Copilot extension installed in VS Code and authenticated
- Git installed
- Working directory: the project root
- GitHub account/remote available and `gh` CLI installed (the PR agent needs `gh auth status` to pass — abort with a clear error message if this fails)

---

## Step-by-Step Instructions

### Step 1.1 — Initialize Git Repository
```bash
git init
git branch -M main
```
Expected result: `.git/` folder created, on `main` branch.

---

### Step 1.2 — Create Directory Tree
Create the following directories (all empty at this stage):

```
.github/
.github/agents/
.github/skills/            (each skill is <name>/SKILL.md)
docs/
user-stories/
src/
tests/
tests/unit/
tests/integration/
tests/fixtures/
output/
output/reports/
output/test-results/
plan/
```

Each empty directory needs a `.gitkeep` file so git tracks it:
- `docs/.gitkeep`
- `user-stories/.gitkeep`
- `src/.gitkeep`
- `tests/unit/.gitkeep`
- `tests/integration/.gitkeep`
- `tests/fixtures/.gitkeep`
- `output/reports/.gitkeep`
- `output/test-results/.gitkeep`

---

### Step 1.3 — Create `.gitignore`
Standard Python gitignore covering:
- `__pycache__/`, `*.pyc`, `*.pyo`, `*.pyd`
- `.env`, `.venv`, `venv/`, `env/`
- `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`
- `dist/`, `build/`, `*.egg-info/`
- `output/test-results/` (gitignored — ephemeral test run data)
- `.DS_Store`, `Thumbs.db`

> **Note**: `output/reports/` is intentionally **not** gitignored — the PR agent reads `output/reports/code-review.md` and embeds it in the PR body.

---

### Step 1.4 — Create `pyproject.toml`
Minimal project metadata:
```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "agentic-sdlc-pipeline"
version = "0.1.0"
description = "Agentic SDLC pipeline driven by GitHub Copilot"
requires-python = ">=3.11"

[tool.pytest.ini_options]
testpaths = ["tests"]

[tool.ruff]
line-length = 88
```

No runtime dependencies yet — the implementation agent will add them during the Phase 6 run.

---

### Step 1.5 — Create `.github/copilot-instructions.md`
This file is loaded automatically by GitHub Copilot into every agent session in this repository. It must explain:

**Sections to include:**
1. **Project Overview** — one paragraph on what this pipeline is and why it exists
2. **How to Run the Pipeline** — exact invocation:
   ```
   Open GitHub Copilot Chat in VS Code
   Select the `orchestrator` agent
   Send: process user-stories/<filename>.md [--fresh]
   ```
3. **Relay-Chain Model** — explain that the orchestrator invokes each specialist agent as a tool, reads its output, asks for human feedback, and passes approved output as input to the next agent
4. **Pipeline Steps** — brief description of each of the 9 steps in order (requirements, architecture, design review, impl planning, implementation, code review, verification, doc sync, PR)
5. **Interaction Levels** — explain L1 (interactive, max 2 rounds), L2 (run + approve/revise/abort), L3 (explicit confirm before PR creation)
6. **File Conventions** — where artifacts live, naming rules for user story files, required fields: Title, Problem Statement, Acceptance Criteria, Constraints, Out of Scope
7. **Do Not** section — list things Copilot should never do: invoke specialist agents directly (users should only ever talk to the orchestrator), skip output gate checks, create the PR without explicit user confirmation, proceed to the next step if the current step's output file is empty

---

### Step 1.6 — Create `README.md`
User-facing documentation. Sections:
1. **What This Is** — 2-3 sentence overview
2. **Quick Start** — 4-step guide: clone, add user story, open Copilot Chat and select `orchestrator` agent, follow prompts
3. **Pipeline Architecture** — ASCII diagram of the relay-chain flow (orchestrator invokes each specialist as a tool → output → human feedback → next agent)
4. **Folder Structure** — annotated tree
5. **Agent Reference** — table of all 9 specialist agents with their role, interaction level, input, and output
6. **Requirements** — GitHub Copilot extension version, Python version (>=3.11), `gh` CLI
7. **Contributing** — how to add a new specialist agent or skill

---

Initialize with a header only. The orchestrator appends a new timestamped entry here after each specialist agent completes and is approved:

```markdown
# Pipeline Changelog

<!-- Entries appended automatically by the orchestrator after each step is approved -->

```
